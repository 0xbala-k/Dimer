# History + Whoop-cycle Days Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a Whoop cycle the unit of a day for both eaten and burned, store past cycles, and build the History tab plus a day detail screen.

**Architecture:** A new `whoop_cycles` table is filled by a client-side sync that runs on app open and foreground, starting from the last saved or unfinished cycle. Pure functions in `lib/days.ts` sort food into cycles by `logged_at` and compute period totals. Screens read only from Supabase.

**Tech Stack:** Expo 54 / expo-router 6, React Native, Supabase JS, Jest (`npx jest`, `logic` project, node env).

**Spec:** `docs/superpowers/specs/2026-11-15-history-design.md`

## Global Constraints

- Burned = `Math.round(kilojoule / 4.184)`; null when the cycle has no score.
- Day label = local date (using the cycle's `timezone_offset`) of `start + 12h`.
- net = burned − eaten; positive = "under", negative = "over".
- Period total excludes "not logged" (burn, no food) and "no Whoop data" (food, no cycle) days; includes the in-progress day.
- Week runs Mon–Sun. Periods: `week | month`. You can't step past the current period.
- First-run backfill from = the later of (earliest `food_logs.logged_at`, now − 30 days); now − 30 days if there are no logs.
- Re-fetch the cycles that are open or `PENDING_SCORE`; `UNSCORABLE` is final.
- Whoop page size 25; follow `next_token`.
- Under uses `colors.primary`; over uses `colors.danger`.
- History is read-only: no delete, edit or add on past days.
- `ConfirmFoodCard` keeps writing `food_logs.date = localDateString()` and stops writing `daily_summaries`.

## Review Focus

1. Cycles whose `timezone_offset` differs from the device (travel) or that cross DST: the label must use the cycle's offset. Pinned in Task 2.
2. Whoop unreachable on open: Today must still show food since the latest stored cycle start, not since local midnight and not empty. Pinned in Task 4 (`currentDayStart`).
3. A `next_token` loop that never ends or an empty page: the sync stops at a missing or empty token and caps at 40 pages. Pinned in Task 3.
4. A food log exactly at a cycle boundary (`logged_at == cycle.end`) goes to the later cycle (half-open interval). Pinned in Task 2.
5. Month view where some days have no data at all (no cycle, no food): show nothing for those days rather than a fake "not logged" row. Pinned in Task 2 (`periodTotal` counts only days that exist).

### Task 2: Day grouping and period math (`lib/days.ts`)

**Files:**
- Create: `lib/days.ts`, `__tests__/days.test.ts`

**Interfaces:**
- Consumes: `WhoopCycleRow`, `FoodLog`, `MacroTotals`.
- Produces:
  ```ts
  dayLabel(startIso: string, tzOffset: string | null): string   // 'YYYY-MM-DD'
  type DayStatus = 'under' | 'over' | 'not_logged' | 'no_whoop' | 'in_progress'
  interface Day {
    key: string                 // String(cycle_id) or 'd-YYYY-MM-DD'
    label: string               // YYYY-MM-DD
    start: string; end: string | null
    cycle: WhoopCycleRow | null
    burned: number | null; eaten: number; net: number | null
    macros: MacroTotals; logs: FoodLog[]
    inProgress: boolean; status: DayStatus
  }
  groupIntoDays(cycles: WhoopCycleRow[], logs: FoodLog[], now?: Date): Day[]   // newest first
  type Period = 'week' | 'month'
  periodRange(period: Period, anchor: Date): { from: string; to: string }  // YYYY-MM-DD inclusive
  shiftAnchor(period: Period, anchor: Date, dir: -1 | 1): Date
  periodTotal(days: Day[]): { net: number; logged: number; total: number }
  ```
  `status`: in_progress if the cycle is open and has food (an open cycle with no food is also in_progress); under/over by the sign of net (net 0 = under); not_logged if there's burn and no logs; no_whoop for fallback days. `net` is null for not_logged and no_whoop. `periodTotal.net` sums days with status under/over/in_progress (in_progress only when net isn't null); `logged` counts those days; `total` = `days.length`.

**Interfaces:**
- Consumes: `groupIntoDays`, `periodRange`, `shiftAnchor`, `periodTotal`, `Day`, `syncCycles`.
- Produces:
  ```ts
  useHistory(period: Period, anchor: Date): { days: Day[]; total: ReturnType<typeof periodTotal>; loading: boolean; error: string | null; refresh: () => Promise<void> }
  useDay(key: string): { day: Day | null; loading: boolean; error: string | null }
  ```
  `useHistory` selects `whoop_cycles` where `day` is between `from` and `to`, and `food_logs` where `logged_at` is within [min(cycle.start, local midnight of from), max(cycle.end ?? now, local end of to)]. It then calls `groupIntoDays` and keeps only days whose label is in range. `refresh` runs `syncCycles()` and then refetches. `useDay` loads a single cycle by id, or a midnight day for `d-…`, with its logs.
